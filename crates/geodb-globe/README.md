# geodb-globe

Interactive 3D globe for `geodb-core`, rendered with wgpu. Click, zoom or search,
and it lists the cities around the centre of view, straight from the embedded database.

One renderer, three front-ends:

| Front-end | Command |
|---|---|
| Web (WebGPU, WebGL2 fallback) | `cd crates/geodb-globe && trunk serve --release` |
| Terminal UI (ratatui) | `cargo run --release -p geodb-globe --features native` |
| Desktop window (winit) | `cargo run --release -p geodb-globe --features native -- --window` |
| Offscreen PNG | `… --features native -- --search Tokyo --screenshot tokyo.png` |

Common options for the native binary: `--search NAME`, `--at LAT,LON`, `--alt KM`, `--size WxH`.
In the web page, append `?gl` to force WebGL2.

## Controls

- **Web / window:** drag to rotate, scroll or pinch to zoom, click to fly there.
- **Terminal:** drag or `hjkl`/arrows to rotate, scroll or `+`/`-` to zoom, and click to fly there.
  `/` searches, `Tab` switches to the list, `↑↓` + `Enter` jumps to a city,
  `1`/`2`/`3` switch between the Globe, accuracy and API bench tabs, `b` re-runs the bench,
  `w` opens the desktop window at the current view, and `q` quits.

The terminal draws the wgpu frame with truecolor half-block characters, so use a
truecolor terminal (`COLORTERM=truecolor`).

## Compare tab: geoid vs. lat/lon

The terminal UI's second tab checks how far you get with the stored 64-bit geoid alone
(for example on a microcontroller that keeps only geoids). The truth is f64 haversine on the
stored latitude/longitude. It shows three things:

- **Where is the selected city?** Its location decoded from the u64 geoid (f64 and f32) and
  from a 4-byte u32 geoid (cell centre), each with the error in metres.
- **Distance from the view centre to every listed city**, for each geoid-only method: mean,
  p99, max and relative error, how often neighbouring cities keep their true order, whether
  the 10 nearest are the same, ns per call on this machine, and what the method needs on an MCU.
- **A per-city table** that follows the list selection.

| Method | Needs | Within ~50 km | At 2 500 km |
|---|---|---|---|
| geoid → f64 haversine | f64 (software on Cortex-M4F) | ≤ 5 mm | ≤ 6 mm |
| geoid → f32 haversine | f32 FPU, sin/cos/asin | ≤ 2 m | ≤ 2 m |
| geoid Δ → f32 flat-earth | f32 FPU, cos, sqrt | ≤ 0.5 m | ≤ 0.54 % |
| geoid Δ → integer flat-earth | integers only | ≤ 0.5 m | ≤ 0.54 % |
| u32 geoid → integer flat-earth | integers only, 4 B/city | ≤ 300 m | ≤ 0.55 % |

Zoom out and the flat-earth methods degrade, which is visible directly in the tab.
`src/geoid.rs` has no allocation and no std-only calls on the integer path:
`distance_mm_fixed` uses a Q30 cosine table (⅛° steps, generated by `build.rs`, about 2.9 KB)
and a 64-bit integer square root, so it ports to firmware as-is.

## API bench tab: lat/lon vs. geoid, CPU vs. GPU

Tab 3 runs the same API calls around the current view in several ways and checks each result
against brute-force f64 haversine on the stored lat/lon:

- **Library call:** `find_cities_in_radius_by_geoid` / `find_nearest`, as the library ships them.
- **lat/lon f64 haversine:** on 1 core and on all cores.
- **Integer geoid** (`dist² ≤ r²`, no square root): on 1 core and on all cores (`std::thread::scope`).
- **GPU** (`src/gpu_query.rs` + `.wgsl`, wgpu compute): raw u64 geoids are uploaded once (1.2 MB),
  and the shader deinterleaves them itself. WGSL has no 64-bit integers, so it uses integer deltas
  plus an f32 flat-earth distance. Timings are full round trips: write params, dispatch, copy back, wait.

Measured on an M2 Max (12 cores, Metal), 153,915 cities:

| Call | Library | geoid int, 1 core | geoid int, 12 cores | GPU |
|---|---|---|---|---|
| radius 56 km, 1 query | 0.53 ms | 0.83 ms | 0.25 ms | 1.3 ms |
| radius 2,500 km, 1 query (≈60k hits) | 3.4 ms | 0.83 ms | 0.30 ms | 2.6 ms |
| 256 radius queries (56 km) | 90 ms | 210 ms | 30 ms | 3–5 ms |
| 10 nearest | 3 µs (Z-order window) | 1.1 ms (brute force) | – | – |

What the numbers show:
- **Integer vs f64:** the integer geoid scan is about 4× faster than the same brute force in f64 haversine.
- **Single queries:** the GPU has a fixed round-trip latency of about 1.3 ms, so a single small
  query is best on CPU cores.
- **Batches:** a batch runs in one dispatch at about 8–12 billion distances/s, 17–30× faster than
  calling the library per query.
- **Accuracy:** every variant is exact at city scale. At 2,500 km the flat-earth geoid methods miss
  about 0.2% of the cities at the rim, and the library misses a few because its longitude bounding
  box is sized at the centre's latitude.

The GPU tests run with `cargo test -p geodb-globe --features native`.

## How the earth texture is made

The texture is baked at start-up (about 0.5 s natively, about 2 s in wasm):

- **Coastlines:** Natural Earth 1:50m land and lakes (public domain, `assets/`), rasterized with anti-aliasing.
- **Deserts vs. fertile land:** settlement density per unit of land from the 150k cities. The Sahara,
  Arabia, the Australian outback and the Gobi all fall out of the data.
- **Night lights:** every city, with national capitals and regional centres brighter.
  The sun position is computed from the current UTC time.

City ranking uses national capital > regional namesake > town, then spreads the
labelled cities apart. The dataset has no city populations.

## Layout

- `camera.rs`: orbit camera, picking, projection.
- `render.rs`: wgpu pipelines (globe, atmosphere, instanced markers), surface and offscreen.
- `texture.rs`, `coast.rs`: texture baking.
- `places.rs`, `view.rs`: queries, ranking, markers.
- `geoid.rs`, `compare.rs`: geoid-only location/distance (MCU-portable) and the comparison.
- `gpu_query.rs`, `gpu_query.wgsl`, `api_bench.rs`: GPU geoid queries and the API benchmark (feature `native`).
- `app.rs`: browser glue.
- `src/bin/geodb-globe/`: native TUI (with the Compare tab) and window.

Data: cities from [dr5hn/countries-states-cities-database](https://github.com/dr5hn/countries-states-cities-database)
(CC-BY-4.0); coastlines from [Natural Earth](https://www.naturalearthdata.com/) (public domain).
