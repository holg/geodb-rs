1. Overview

This guide documents how we built a native Android app in Kotlin that uses a Rust backend for geographic data lookups. The app provides fast city search across 150,000+ cities worldwide, powered by the same Rust engine used in our iOS, watchOS, and macOS apps.

The Stack:

  • Backend: Rust (geodb-core library)
  • FFI Bridge: Mozilla UniFFI
  • Android UI: Kotlin + Jetpack Compose
  • Build Tool: cargo-ndk

Why Rust for Android?

  • Share business logic across iOS, Android, and other platforms
  • Native performance without JNI boilerplate
  • Memory safety guarantees
  • UniFFI generates idiomatic Kotlin code automatically

4. Installing Android Rust Targets

Android devices use different CPU architectures. We need to install Rust targets for each:

# 64-bit ARM (most modern phones)
rustup target add aarch64-linux-android

# 32-bit ARM (older phones)
rustup target add armv7-linux-androideabi

# 64-bit x86 (emulators, Chromebooks)
rustup target add x86_64-linux-android

# 32-bit x86 (older emulators)
rustup target add i686-linux-android

# Verify installation
rustup target list --installed | grep android

5. Setting Up the Rust FFI Crate

The UDL File (Interface Definition)

UniFFI uses a UDL (Universal Definition Language) file to define the API exposed to Kotlin:

// crates/geodb-ffi/src/geodb.udl

namespace geodb_ffi {
    // Initialize the database (call once at app start)
    void init_db();

    // Smart search with limit
    sequence<CityResult> smart_search(string query, u32 limit);

    // Get database statistics
    DbStats get_db_stats();

    // Search by coordinates
    sequence<CityResult> search_by_location(f64 lat, f64 lon, f64 radius_km, u32 limit);
};

dictionary CityResult {
    string name;
    string state_name;
    string country_name;
    string country_iso2;
    f64 latitude;
    f64 longitude;
    u32 score;
};

dictionary DbStats {
    u32 country_count;
    u32 state_count;
    u32 city_count;
};

Cargo.toml Configuration

[package]
name = "geodb-ffi"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib", "staticlib"]
name = "geodb_ffi"

[dependencies]
uniffi = { version = "0.30", features = ["cli"] }
geodb-core = { path = "../geodb-core", default-features = false, features = ["json", "compact", "search_blobs"] }
once_cell = "1.19"

[build-dependencies]
uniffi = { version = "0.30", features = ["build"] }

[[bin]]
name = "uniffi-bindgen"
path = "uniffi-bindgen.rs"
Important: We disable the builder feature in geodb-core. This removes the reqwest dependency which pulls in ring for TLS. The ring crate has issues with some Android ABIs (especially older 32-bit targets). Since we embed the data, we don't need HTTP anyway.

6. Building Native Libraries

Using cargo-ndk

cargo-ndk simplifies cross-compilation for Android by handling all the NDK toolchain setup:

# Build for all Android architectures
cargo ndk \
    -t arm64-v8a \
    -t armeabi-v7a \
    -t x86_64 \
    -t x86 \
    -o target/android-libs \
    build --release -p geodb-ffi

What this does:

  1. Finds the Android NDK automatically
  2. Sets up the correct linker for each target
  3. Cross-compiles the Rust code
  4. Copies the .so files to target/android-libs/

Output structure:

target/android-libs/ ├── arm64-v8a/ │ └── libgeodb_ffi.so (8.4 MB) ├── armeabi-v7a/ │ └── libgeodb_ffi.so (8.2 MB) ├── x86_64/ │ └── libgeodb_ffi.so (8.5 MB) └── x86/ └── libgeodb_ffi.so (8.5 MB)

7. Generating Kotlin Bindings

UniFFI generates idiomatic Kotlin code from the compiled library:

# Generate Kotlin bindings from the Android library
cargo run --features=uniffi/cli --bin uniffi-bindgen \
    generate \
    --library target/aarch64-linux-android/release/libgeodb_ffi.so \
    --language kotlin \
    --out-dir generated-kotlin

Generated file: generated-kotlin/uniffi/geodb_ffi/geodb_ffi.kt

This generates a ~68KB Kotlin file containing:

  • Data classes (CityResult, DbStats)
  • Function wrappers (initDb(), smartSearch())
  • JNA bindings for native calls
  • Error handling and type conversions

Generated Code Example

// Auto-generated by UniFFI
package uniffi.geodb_ffi

data class CityResult(
    val name: String,
    val stateName: String,
    val countryName: String,
    val countryIso2: String,
    val latitude: Double,
    val longitude: Double,
    val score: UInt
)

fun smartSearch(query: String, limit: UInt): List<CityResult> {
    return uniffiRustCall { status ->
        UniffiLib.INSTANCE.uniffi_geodb_ffi_fn_func_smart_search(
            FfiConverterString.lower(query),
            FfiConverterUInt.lower(limit),
            status
        )
    }.let {
        FfiConverterSequenceTypeCityResult.lift(it)
    }
}

        compose = true
    }

    composeOptions {
        kotlinCompilerExtensionVersion = "1.5.6"
    }

    sourceSets {
        getByName("main") {
            // Tell Gradle where to find our native libraries
            jniLibs.srcDirs("src/main/jniLibs")
        }
    }
}

dependencies {
    // Jetpack Compose
    implementation(platform("androidx.compose:compose-bom:2023.10.01"))
    implementation("androidx.compose.ui:ui")
    implementation("androidx.compose.material3:material3")
    implementation("androidx.activity:activity-compose:1.8.2")

    // JNA - Required for UniFFI bindings
    implementation("net.java.dev.jna:jna:5.14.0@aar")
}
Key Dependency: The net.java.dev.jna:jna library is essential. UniFFI uses JNA (Java Native Access) to call into the Rust library. Without it, you'll get runtime crashes.

9. Building the UI with Jetpack Compose

MainActivity.kt

package eu.trahe.geodb

import android.os.Bundle
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.compose.foundation.layout.*
import androidx.compose.foundation.lazy.LazyColumn
import androidx.compose.foundation.lazy.items
import androidx.compose.material3.*
import androidx.compose.runtime.*
import androidx.compose.ui.Alignment
import androidx.compose.ui.Modifier
import androidx.compose.ui.unit.dp
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.launch
import kotlinx.coroutines.withContext
import uniffi.geodb_ffi.*

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            MaterialTheme {
                GeoDBScreen()
            }
        }
    }
}

@Composable
fun GeoDBScreen() {
    var searchQuery by remember { mutableStateOf("") }
    var searchResults by remember { mutableStateOf<List<CityResult>>(emptyList()) }
    var isInitialized by remember { mutableStateOf(false) }
    var dbStats by remember { mutableStateOf<DbStats?>(null) }

    val coroutineScope = rememberCoroutineScope()

    // Initialize database on first composition
    LaunchedEffect(Unit) {
        withContext(Dispatchers.IO) {
            initDb()  // Call Rust function
            isInitialized = true
            dbStats = getDbStats()  // Get stats from Rust
        }
    }

    Column(modifier = Modifier.fillMaxSize().padding(16.dp)) {
        // Header with stats
        Text("GeoDB", style = MaterialTheme.typography.headlineLarge)
        dbStats?.let { stats ->
            Text("${stats.countryCount} countries, ${stats.cityCount} cities")
        }

        Spacer(modifier = Modifier.height(16.dp))

        // Search field
        OutlinedTextField(
            value = searchQuery,
            onValueChange = { newQuery ->
                searchQuery = newQuery
                if (newQuery.length >= 2 && isInitialized) {
                    coroutineScope.launch {
                        withContext(Dispatchers.IO) {
                            // Call Rust search function
                            searchResults = smartSearch(newQuery, 20u)
                        }
                    }
                }
            },
            label = { Text("Search cities...") },
            modifier = Modifier.fillMaxWidth(),
            enabled = isInitialized
        )

        // Results list
        LazyColumn {
            items(searchResults) { city ->
                CityCard(city)
            }
        }
    }
}

@Composable
fun CityCard(city: CityResult) {
    Card(modifier = Modifier.fillMaxWidth().padding(vertical = 4.dp)) {
        Column(modifier = Modifier.padding(16.dp)) {
            Text(city.name, style = MaterialTheme.typography.titleMedium)
            Text("${city.stateName}, ${city.countryName}")
            Text("📍 ${city.latitude}, ${city.longitude}")
        }
    }
}

Key Points

  1. IO Dispatcher: Always call Rust functions on Dispatchers.IO to avoid blocking the main thread
  2. One-time initialization: initDb() loads the embedded database (~50ms)
  3. Automatic type conversion: UniFFI converts Rust types to Kotlin automatically

# proguard-rules.pro

# Keep JNA classes
-keep class com.sun.jna.** { *; }
-keep class * implements com.sun.jna.** { *; }

-keep class uniffi.** { *; }

12. Lessons Learned

1. cargo-ndk is Essential

Don't try to set up Android cross-compilation manually. cargo-ndk handles all the complexity:

# Bad: Manual NDK setup (error-prone)
export CC_aarch64_linux_android=...
export AR_aarch64_linux_android=...
export CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER=...

# Good: Let cargo-ndk handle it
cargo ndk -t arm64-v8a build --release

2. JNA Dependency is Critical

UniFFI-generated Kotlin code uses JNA. Without the @aar suffix, you might get the wrong artifact:

// Wrong - gets JAR without Android support
implementation("net.java.dev.jna:jna:5.14.0")

// Right - gets AAR with Android native libs
implementation("net.java.dev.jna:jna:5.14.0@aar")

3. Feature Flags Matter

We disabled the builder feature to avoid the ring crate. This pattern is useful:

# geodb-core Cargo.toml
[features]
default = ["json", "builder", "compact"]
builder = ["dep:reqwest"]  # Pulls in TLS/crypto

# geodb-ffi Cargo.toml - for Android
geodb-core = { path = "../geodb-core", default-features = false, features = ["json", "compact"] }

4. Use Dispatchers.IO

Rust FFI calls should never run on the main thread:

// Bad - blocks UI
val results = smartSearch(query, 20u)

// Good - runs on IO thread
withContext(Dispatchers.IO) {
    val results = smartSearch(query, 20u)
}

5. App Bundles Reduce Size

Google Play Store supports App Bundles that deliver only the needed ABI to each device. A 35MB universal APK becomes ~10MB per device.

Quick Start Script

Here's a complete script to build the Android libraries from scratch:

#!/bin/bash
set -e

echo "=== Building GeoDB for Android ==="

# 1. Install targets if needed
echo "Installing Android Rust targets..."
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android i686-linux-android

# 2. Build native libraries
echo "Building native libraries..."
cd crates/geodb-ffi
cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 -t x86 -o ../../target/android-libs build --release

# 3. Generate Kotlin bindings
echo "Generating Kotlin bindings..."
cargo run --features=uniffi/cli --bin uniffi-bindgen generate \
    --library ../../target/aarch64-linux-android/release/libgeodb_ffi.so \
    --language kotlin \
    --out-dir ../../generated-kotlin

# 4. Copy to Android project
echo "Copying to Android project..."
cp -r ../../target/android-libs/* ../../GeoDB-App/android-app/app/src/main/jniLibs/
cp -r ../../generated-kotlin/uniffi ../../GeoDB-App/android-app/app/src/main/java/

echo "=== Done! ==="
echo "Open GeoDB-App/android-app in Android Studio to build the APK"

Conclusion

Building Android apps with Rust is surprisingly smooth thanks to:

  • cargo-ndk: Handles all cross-compilation complexity
  • UniFFI: Generates idiomatic Kotlin bindings automatically
  • JNA: Provides the native call infrastructure

The result is a native Android app with:

  • Shared business logic with iOS/macOS/watchOS
  • Native performance (sub-5ms search)
  • Type-safe API (no manual JNI)
  • ~10MB per-device footprint via App Bundles

The same Rust core powers all our platforms, with platform-specific UIs on top. Write once, run everywhere - but actually native.
